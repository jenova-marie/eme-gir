Eme-gir

A locally-mirrored research surface over four bulk academic archives of the Sumerian textual record — the dictionary, the annotated corpus, the literary canon, and the artifact catalogue — indexed for sub-millisecond query and exposed to language models via the Model Context Protocol.

About this project

The University of Pennsylvania's electronic Pennsylvania Sumerian Dictionary, second edition (ePSD2), is the standard modern lexical resource for Sumerian — published in 2017 by an international team led by Dr. Steve Tinney and integrated with the Open Richly Annotated Cuneiform Corpus (Oracc), a federated archive of roughly 138,000 transliterated cuneiform texts from museum collections in London, Berlin, Philadelphia, Istanbul, and Baghdad. Alongside Oracc, the Oxford Electronic Text Corpus of Sumerian Literature (ETCSL) contributes 394 hand-lemmatized literary compositions — hymns, myths, royal hymns, proverbs, the Sumerian King List, Inana's Descent, Gilgameš and the Underworld, the Šulgi praise poems — shipped with English translations alongside every Sumerian line. The Cuneiform Digital Library Initiative (CDLI) supplies catalogue metadata for 353,000 cuneiform-bearing artifacts: provenience, period, museum custody, dimensions, publication history, and links to the institutionally-hosted photographs and line drawings.

Each archive is distributed in a format suited to its own publication tradition — Oracc as 208 zipped JSON projects (~3.1 GB), ETCSL as TEI XML from the Oxford Text Archive, CDLI as a Git-LFS-hosted CSV — and excellent for almost nothing in particular until infrastructure is built on top of it. This project is that infrastructure. Streaming parsers ingest the source archives into denormalized SQLite indexes with FTS5 over Sumerian transliteration and English translation, bringing every operation — point lookup, attestation join, n-gram pattern query, line-with-lemma search — down to a local SQLite call typically under fifty milliseconds.

The surface this exposes is twofold: a Flask web application that recreates the canonical Oracc browsing experience offline with cuneiform-glyph rendering and attestation-line context, and a constellation of five Model Context Protocol servers organized along clean data-source boundaries (ePSD2, ETCSL, CDLI, OGSL sign list, and a teaching surface in the persona of Ummia 𒌝𒈪𒀀, the master teacher of the Sumerian scribal school). The MCP servers are designed around an attestation-first contract for language models: instead of letting LLMs confabulate plausible-looking morphology for a sparsely-trained, ergative-absolutive isolate, every tool returns real corpus forms ranked by frequency, with cited tablet sources, and every cited tablet links straight to its CDLI-hosted photograph. The agent's job is to choose; the corpus's job is to constrain.

Scope & purpose

This project is not a turnkey English-to-Sumerian translation system, and should not be used as one. Sumerian is an extinct, ergative-absolutive language isolate with a four-millennium attestation history spanning multiple dialects, registers, and orthographic conventions; competent translation requires a reader who can adjudicate among homographs, choose a historical period, weigh literary register against administrative register, and recognize when the corpus is silent on a construction. No language model — and no dictionary lookup chain, however well-grounded — can substitute for that judgment.

What this project does offer is a set of carefully indexed reference surfaces designed to aid the work of a human translator, student, or researcher who already brings (or is acquiring) that judgment. For the working scholar, the MCP servers function as a high-throughput lookup harness: attestation joins, n-gram pattern queries, period filters, and cross-references that would otherwise require hand-scraping Oracc's HTML pages. For students, the Ummia teaching server ships a structured five-lesson Sumerian 101 curriculum with a master-teacher persona, drill exercises, and seamless routing into the data servers for live vocabulary lookups and attested examples. For LLM agents, the attestation-first design constrains the model to real corpus forms — surfacing what scribes actually wrote so the human in the loop has authentic material to evaluate, rather than plausible-looking confabulation to cross-check.

The intended user is, in every case, a person doing the scholarship — the agent is a research instrument, not a replacement for the act of translation.

Connect via MCP

The Model Context Protocol is an open standard, originally introduced by Anthropic in November 2024, that lets language models call out to external tools, query databases, and read files through a uniform JSON-RPC interface — analogous to what a Language Server Protocol does for code editors, but for AI agents. An MCP server is the backend system the agent talks to; an MCP client is the agent runtime — Anthropic's Claude Desktop and Claude Code, OpenAI's ChatGPT (desktop and web, via its connectors / custom-MCP interface), Google's Gemini (via Gemini Code Assist and the Gemini CLI's MCP support), Cursor, Zed, or an LLM wrapper of your own. Eme-gir is that backend system for the Sumerian textual record — five independent MCP servers, one per data source, each surfacing its archive as a coherent set of tools the agent can invoke during a research or teaching session.

🌐 Open to the public, read-only, no authentication required. OAuth is intentionally disabled on the public deployment so any MCP-compatible client can connect without provisioning credentials. All tools are read-only over local SQLite — no write surface exists. Please be courteous to the small server fronting these endpoints; for heavy workloads, clone the repository and run the stack locally via docker compose up.

How to use

Once your client is configured and the five servers are reachable, the MCP handshake establishes a session — but the agent is still naïve about how each server expects to be used. Each server therefore ships a start_here() bootstrap tool whose docstring is prefixed with the literal sentinel ⭐ CALL THIS FIRST, so a tools-list scan surfaces it as the entry point. Calling it loads the per-server operating instructions into the agent's context: how to compose with sibling servers, which tools to reach for in what order, what the response shapes mean, and (on Ummia) the teaching persona itself. There are two recommended starting paths depending on what you want to do.

Path A — Research & translation

📚 Load the four data servers

For English ↔ Sumerian dictionary lookup, lexical research, lemma attestation, literary corpus queries, and artifact provenience research. Begin every session by issuing this single bootstrap prompt to your agent:

use the start_here tool of mcp servers eme-gir-epsd2, eme-gir-etcsl, eme-gir-cdli, eme-gir-ogsl

💡 Re-issue periodically. Long sessions cause agents to drift from the bootstrap context as the conversation history grows. If responses start ignoring attestation-first guidance, skipping the sense_count/sense_pct ranking, or omitting cited links, just paste this prompt again to refresh the per-server operating instructions. The start_here calls are idempotent — repeated invocations are cheap and won't break anything.

The agent will then have the operating context to answer queries by routing them to the appropriate server. Try:

  • "What is the Sumerian word for 'temple'? Show me three attested spellings with cuneiform glyphs."
  • "Find me an Ur III administrative line where lugal appears with the verb du₃."
  • "Translate lugal-e e₂ mu-na-du₃ and parse the grammatical role of each token."
  • "In the Sumerian King List (ETCSL c.2.1.1), show me the first ten lines bilingually."
  • "Find every Ur III tablet from Drehem held by the British Museum that has a published photograph."

Path B — Guided instruction

𒌝𒈪𒀀 Begin a session with Ummia

For learning Sumerian from the ground up — phonology, the verbal chain, the case system, modal prefixes, subordination — taught one-on-one by the master scribe of the temple school in the persona of Ummia. Begin with:

use the start_here tool of mcp server eme-gir-ummia

💡 Re-issue periodically. Long teaching sessions cause the Ummia persona to drift as the lesson transcript grows — voice flattens, the scribal frame slips, drills get skipped. Paste this prompt again at the start of each new lesson (or any time the persona feels off) to re-anchor the master-scribe voice and the lesson workflow. The call is idempotent and won't disrupt in-flight conversation.

The agent adopts the teaching persona, surfaces the five-lesson Sumerian 101 curriculum, and waits for you to name where you'd like to begin. Try:

  • "I'm new to Sumerian — start with lesson 101-1."
  • "Teach me the case system." (routes to 101-3)
  • "I want to compose a temple prayer — what should I know first?"
  • "Explain the difference between the perfective and the imperfective."

For best results, also load the four data servers above — Ummia routes vocabulary lookups, attested examples, and cuneiform rendering to the data tools while teaching.

Both bootstrap tools are idempotent — calling start_here() a second time within a session is a no-op. After the initial handshake, simply request lookups, translations, attestations, or lessons in natural language; the agent's loaded context dictates which server's tools to invoke for any given question.
